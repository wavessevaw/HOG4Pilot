# Архитектура и внутренние интерфейсы

Поток: намерение → Lighting → Safety → ValidatedFrame → Output.

Реализованные модули:

| Модуль | Контракт |
|---|---|
| fixture | Profile содержит версию, источник, каналы и проверенность; Fixture связывает профиль с адресом 1–512 |
| lighting | Look::validate проверяет конечные нормированные значения; fade возвращает промежуточное состояние, не отправляет данные |
| safety | new проверяет патч и полный baseline; render проверяет источник и намерение; stop блокирует следующие render; journal — журнал в памяти |
| output | Output::send принимает только ValidatedFrame; Simulator сохраняет кадры; ArtNet отправляет UDP, возвращает транспортную ошибку |

Baseline — подтверждённый полный кадр конкретной вселенной, а не автоматически выбранные нули. Нули допустимы в встроенной синтетической модели. Locked всегда сохраняет neutral; пользовательское намерение не содержит служебных команд. Разрешённый диапазон канала должен целиком соответствовать безопасной непрерывной функции.

Граница доверия текущего прототипа — Rust приложение. Поля профилей открыты для доверенного загрузчика, а конструктор кадра недоступен внешнему коду. Защита от недоверенного профиля требует отдельного реестра подтверждений и хранения происхождения.

Следующие этапы: SQLite миграции и репозиторий профилей; выделенный output worker с watchdog и остановкой через независимый канал; Tauri IPC с намерениями вместо кадров; React UI; далее Discovery, Venue, Show, Hog Adapter, Assistant. Эти интерфейсы пока не реализованы. Hog должен по умолчанию оставаться без изменения шоу; команды и обратная связь требуют проверки по указанной пользователем документации.

Windows: Rust core использует только стандартную библиотеку и переносимые UDP API. Сборка и выполнение на Windows ещё не проверены; Linux бинарник не является Windows релизом.
